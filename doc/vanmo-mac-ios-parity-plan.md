# Vanmo Mac 与 Vanmo iOS 功能完成度对比及未来实现计划

> 参考文档：`doc/vanmo-ios-current-requirements.md`、`doc/mac-todo.md`  
> 生成时间：2026-07-07  
> 目的：以 iOS 当前产品能力为基线，评估 Vanmo Mac 当前完成度、剩余差距、优先级和后续实现路线。

---

## 1. 结论摘要

Vanmo iOS 仍是当前功能最完整的平台，可作为 macOS 独立版本的产品基线。按照 `doc/mac-todo.md` 的最新状态，Vanmo Mac 已经完成从“基础骨架”到“核心 MVP parity”的主要跨越：应用壳层、连接浏览、媒体库首页、搜索、详情页交互、设置页、AVPlayer 播放器增强、部分 KSPlayer 特殊格式路径、桌面交互打磨均已接入。

当前 Mac 版已经具备“添加连接 → 浏览或扫描 → 媒体库聚合 → 搜索 → 详情 → 播放 → 进度/收藏 → 设置偏好”的主链路。剩余差距主要不再是基础产品闭环，而集中在以下几类：

- iOS 已产品化但 Mac 延后的能力：部分字幕配置入口。
- iOS 自身也未完全产品化或待验证的能力：国际网盘端到端验证、FTP/SFTP/NFS/DLNA、ISO/libbluray/UDF、下载中心、Trakt、TMDb 独立刮削。
- Mac 专属发布质量事项：macOS CI、CloudKit Release entitlement 验证、双端 schema 测试、桌面体验细节收尾。
- 需要实机或真实账号验证的能力：CloudKit 双端同步、OAuth 网盘、百度网盘官方能力、媒体服务器差异、KSPlayer 特殊编码。

以 iOS 完整能力为 100% 基线，Vanmo Mac 当前估算如下：

| 范围 | Mac 当前完成度 | 判断 |
|------|----------------|------|
| 核心 MVP 链路 | 85%–90% | 主路径已完成，剩余以验证和少量延后项为主 |
| iOS 已产品化功能 parity | 70%–80% | 部分在线字幕/验证项仍缺 |
| 全量需求 parity（含 iOS 占位和待验证） | 60%–70% | 多数高级协议和原盘能力本身不是 iOS 已闭环能力 |
| 发布可用度 | 65%–75% | 需要 CI、Release CloudKit、端到端回归补齐 |

## 2. 对比口径

### 2.1 状态定义

| 状态 | 含义 |
|------|------|
| 已完成 | Mac 已有明确实现，且与 iOS 主行为基本对齐 |
| 基本完成 | 主链路可用，但仍需验证、体验补齐或边界修正 |
| 部分完成 | 有入口或局部能力，尚不能等价替代 iOS |
| 延后 | 明确不在当前 Mac 主路径，后续单独排期 |
| 共性待办 | iOS 与 Mac 都不是完整产品化能力 |

### 2.2 完成度评估原则

1. iOS 文档描述的“已产品化”能力优先纳入 parity 对比。
2. iOS 文档中标注“协议已实现，待端到端验证”的能力，不把 Mac 缺失视为最高优先级，但需要进入未来计划。
3. iOS 文档中明确为“占位”“壳实现”“未产品化”的能力，Mac 不应为了追平而提前承诺完整实现。
4. Mac 的桌面特性不是简单复制 iOS UI，而是复用 `VanmoCore` 和业务规则，采用 macOS 原生导航、菜单、快捷键、拖拽、Quick Look 等交互。

## 4. iOS 已产品化而 Mac 仍需补齐的重点差距

### 4.1 字幕服务配置入口

**iOS 能力：**

- OpenSubtitles API Key。
- OpenSubtitles 账户测试。
- Shooter / Subhd 有 Provider 壳，但待产品化。

**Mac 当前状态：**

- 播放器已注册在线字幕 Provider，并支持搜索、下载、加载。
- 设置页字幕偏好已覆盖字号、语言、颜色、背景、位置。
- 文档中对 OpenSubtitles 配置入口仍有“待补/需核对”的痕迹。

**实现计划：**

| 步骤 | 优先级 | 内容 | 验收 |
|------|--------|------|------|
| SUB-1 | P1 | 核对 Mac 设置页是否已有 OpenSubtitles API Key 输入和测试入口 | 可保存 API Key 并执行测试 |
| SUB-2 | P1 | 播放器在线字幕搜索读取同一凭据 | 无凭据时提示明确 |
| SUB-3 | P2 | Shooter/Subhd 配置策略定稿 | 没有可用 endpoint 时不展示误导入口 |
| SUB-4 | P2 | 下载字幕缓存管理 | 下载后可重复选择，缓存可清理 |

### 4.2 CloudKit Release 验证

**iOS 能力：**

- Debug 不带 iCloud entitlement。
- Release 带 CloudKit entitlement，并通过 `CLOUDKIT_SYNC_ENABLED` 启用。
- 同步 SavedConnection、FolderBookmark、CloudMediaState。

**Mac 当前状态：**

- 生命周期、播放进度、收藏、书签同步触发已经接线。
- 仍需验证 `Vanmo-Mac-Cloud.entitlements` 和 Release 构建下的真实双端同步。

**实现计划：**

| 步骤 | 优先级 | 内容 | 验收 |
|------|--------|------|------|
| SYNC-1 | P0 | 增加 macOS Release 构建检查 | Release target entitlement 正确 |
| SYNC-2 | P0 | iOS 添加连接 → Mac 启动同步 | Mac 能看到非敏感连接配置 |
| SYNC-3 | P0 | Mac 收藏/进度 → iOS 同步 | iOS 继续观看和收藏状态更新 |
| SYNC-4 | P1 | 删除连接清理书签和扫描项回归 | 不影响其他连接数据 |
| SYNC-5 | P1 | 冲突规则回归 | 最近更新时间、收藏、进度合并符合预期 |

## 5. 共性待办：不应作为 Mac 追赶的最高优先级

以下能力在 iOS 文档中也不是完整闭环。Mac 后续可以规划，但不应阻塞 Mac MVP 发布。

| 能力 | iOS 状态 | Mac 策略 |
|------|----------|----------|
| Google Drive / OneDrive / Box / pCloud / Yandex.Disk | 协议已实现，待真实凭据端到端验证 | 先确保 Mac 复用核心 OAuth、取流和下载路径，再按账号逐项验证 |
| 百度网盘 | 官方合规接入，仍需官方参数和限速策略验证 | 不做非官方接口；先验证浏览和播放前解析 |
| 115 / 夸克 / MEGA | 合规占位 | Mac 保持占位，不提前实现私有接口 |
| FTP / SFTP | 壳实现，无真实浏览播放 | 除非用户需求明确，否则延后 |
| NFS / DLNA | 壳实现，无真实浏览播放 | 延后到局域网协议专项 |
| ISO 完整解析 | 未实现 | 保持明确提示和 fallback，不承诺完整原盘 |
| libbluray / UDF | 未实现 | 需要独立技术评估和许可证评估 |
| 远程 BDMV 随机读 | 未实现 | 不进入近期计划 |
| Trakt 同步 | 未实现 | 双端都延后 |
| TMDb 独立刮削 | 未实现 | 当前元数据仍以媒体服务器和缓存为主 |
| 后台下载中心 | 未产品化 | 可作为 v1.2+ 独立功能 |
| tvOS | 未做 | 与 Mac parity 无关 |

## 6. 未来实现路线图

### 6.1 近期目标：Mac MVP 发布前收口

**目标：** 把已经完成的核心能力从“开发完成”推进到“可发布、可回归、可验收”。

| 编号 | 优先级 | 任务 | 预估 | 验收 |
|------|--------|------|------|------|
| MVP-1 | P0 | 跑通 macOS xcodebuild / CI | 1–2 天 | `Vanmo-macOS` CI 通过 |
| MVP-2 | P0 | CloudKit Release entitlement 和双端同步验证 | 1–2 天 | 连接、书签、进度、收藏 iOS/Mac 双向同步 |
| MVP-3 | P0 | 核心端到端回归：本地文件夹、SMB、WebDAV、Emby/Jellyfin、Plex | 2–3 天 | 添加/浏览/扫描/详情/播放/进度闭环可用 |
| MVP-4 | P1 | 字幕配置入口核对与 OpenSubtitles 登录测试 | 1 天 | 搜索下载在线字幕可用，无凭据提示清晰 |
| MVP-5 | P1 | KSPlayer 特殊格式回归 | 1–2 天 | MKV 等路径可播放；ISO/MPLS/BDMV 不支持时提示明确 |
| MVP-6 | P1 | macOS 桌面交互回归 | 1 天 | 右键菜单、Quick Look、拖拽播放、菜单栏控制、快捷键可用 |
| MVP-7 | P1 | 文案和空状态统一 | 1 天 | 无连接、空目录、播放失败、OAuth 未配置都有明确提示 |

**MVP 出口标准：**

1. 用户能在 Mac 上添加至少本地文件夹、SMB/WebDAV、Emby/Jellyfin/Plex 中的一类来源。
2. 用户能浏览目录或媒体库、进入详情、播放视频。
3. 播放进度、收藏、书签能按设计同步或明确说明不参与同步。
4. 字幕、倍速、全屏、快捷键、自动下一集在常见 AVPlayer 路径下可用。
5. Debug/Release 的 CloudKit 行为符合签名和账号规则。
6. 对未支持协议和特殊格式不误导用户。

## 7. 端到端验收清单

### 7.1 连接与浏览

- 添加本地文件夹连接后能保持授权、浏览、播放。
- 添加 SMB/WebDAV/AList/fnOS 后能连接、浏览、递归扫描、播放。
- 删除连接时清理关联书签和扫描库，不影响其他连接。
- OAuth 未配置、登录取消、token 过期、路径不存在时提示明确。
- 文件夹书签能在浏览页添加/取消，并能从首页跳回目标目录。

### 7.2 媒体库

- 首页展示继续观看、收藏、文件夹书签、媒体服务器虚拟库、扫描库。
- Emby/Jellyfin/Plex 连接后能展示服务器库预览。
- 扫描库电影和剧集能合理分组。
- 子列表支持网格/列表切换和排序。
- 详情页能播放、收藏、标记已看、刷新元数据、查看季集和合集。

### 7.3 搜索

- 搜索能覆盖本地扫描库。
- 搜索能覆盖 Emby/Jellyfin/Plex live API。
- 支持按来源分组展示结果。
- 点击搜索结果能进入详情或播放。
- 无结果和远程搜索失败不阻断整个搜索体验。

### 7.4 播放器

- AVPlayer 路径支持播放/暂停、进度拖动、快进快退、倍速、全屏、快捷键。
- 播放关闭后写回进度，并进入继续观看。
- 直播内容不写入断点续播。
- 内嵌字幕、外挂字幕、在线字幕可选择和显示。
- 音轨/字幕轨选择可用。
- 自动下一集读取设置并按剧集顺序播放。
- MKV 或特殊编码走 KSPlayer 路径；不支持的 ISO/MPLS/BDMV 场景提示明确。

### 7.5 同步与设置

- Debug 构建不因 iCloud entitlement 签名失败。
- Release 构建带正确 CloudKit entitlement。
- SavedConnection、FolderBookmark、CloudMediaState 能在 iOS 与 Mac 间同步。
- 密码和 OAuth token 不进入 CloudKit。
- 设置页修改播放、字幕、媒体库、外观、缓存等偏好后能影响对应功能。

### 7.6 macOS 原生体验

- 侧边栏导航状态稳定，搜索、设置、详情、连接浏览互不覆盖。
- 右键菜单可用于播放、Quick Look、编辑、删除、重扫等动作。
- 拖拽本地视频到窗口可播放。
- 菜单栏控制能反映当前播放状态。
- 快捷键不会在输入框焦点下误触发破坏性操作。

## 8. 风险与注意事项

### 8.1 文档状态风险

`doc/mac-todo.md` 中早期“Mac 距 iOS MVP parity 约 40–50% 功能缺口”的估算已经与当前完成快照不完全一致。后续应以该文档顶部“当前进度快照”和各阶段 checkbox 为准，必要时清理旧估算，避免误判。

### 8.2 CloudKit 和账号风险

CloudKit、OAuth 网盘、百度网盘官方接口都依赖真实账号、entitlement、开发者后台配置和服务端策略。代码接线完成不等于产品验证完成，发布前必须用真实环境回归。

### 8.3 特殊格式风险

KSPlayer / FFmpeg 可以覆盖一部分 AVFoundation 不支持的格式，但完整 ISO、蓝光菜单、libbluray、UDF、远程 BDMV 随机读都不是当前已承诺能力。UI 文案必须明确“部分支持”或“不支持”，不能暗示完整原盘播放器。

### 8.4 合规风险

115、夸克、MEGA、百度网盘等来源必须坚持官方和合规接口原则。没有官方开放能力时，应展示暂不支持或待审核提示，不使用 Cookie、抓包、逆向或私有接口。

### 8.5 桌面体验风险

Mac 不应机械复刻 iOS Tab 页面。侧边栏、右键菜单、拖拽、Quick Look、菜单栏、快捷键、多窗口等桌面体验应成为 Mac 的设计重点，但不能破坏与 iOS 一致的数据规则和同步边界。
