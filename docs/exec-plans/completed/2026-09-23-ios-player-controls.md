# iOS Player Controls

**Status:** Completed
**Related product spec:** [`../../product-specs/ios-player-controls.md`](../../product-specs/ios-player-controls.md)
**Related reliability authority:** [`../../RELIABILITY.md`](../../RELIABILITY.md)

## Objective

Add iOS seek-preview frames, a client-side quality cap, skip-intro with marker plus manual memory, and an AirPlay route control without changing macOS playback or adding AI enhancement.

## Scope

- iOS player chrome, `PlayerViewModel`, and AV/KS engine adapters
- Shared intro-window resolution, quality preference, and Emby/Jellyfin/Plex marker fetch
- iOS Figma Player page `599:3`

## Out of Scope

- macOS player
- Emby/Plex server transcode selection
- AI quality enhancement
- Chromecast / DLNA
- CloudKit schema changes for intro marks

## Verification

1. `swift test --package-path Packages/VanmoCore` covers intro matching, marker parsing, and quality mapping
2. `./scripts/check-app-build.sh ios-simulator` compiles the iOS app
3. Simulator walk: slider preview, gesture preview, quality capsule, skip intro after a manual mark
4. Physical-device walk: AirPlay picker and either video AirPlay or the unsupported-format notice

A package test or compile is not Simulator UI evidence. Simulator UI is not AirPlay evidence.

## Risks

- SMB/FTP/SFTP preview can only use live cached frames
- Local files and SMB/FTP/SFTP do not gain a lower-bitrate stream when quality changes
- Media-server transcode startup can delay the first frame after a quality change
- KSPlayer cannot send FFmpeg frames to Apple TV
- Before a source opens, the quality circle briefly shows the saved preference; it switches to 原画 once a direct bitstream reports ready
- A remote single-rendition HLS playlist, or a master whose renditions all exceed the cap, plays above the cap on AVPlayer while the circle still shows the requested height
- On KSPlayer, a seek while paused (Skip Intro or rewind) keeps the previous frame until Play
- The English UI shows untranslated `快退`, `快进`, and `缩放` accessibility labels and the `倍速` context-menu item
- A quality switch keeps the frozen picture until the new source reports a frame while audio already plays (about 1.5 seconds after ready on KSPlayer for Emby item 253013); a source that reports no frame keeps the cover for up to 3 seconds
- AVPlayer keeps one decoded pixel buffer referenced during playback for the hold frame; its memory and HDR or 4K cost has no device measurement. The AVPlayer hold frame ignores the track's `preferredTransform` and renders HDR as SDR, so a rotated or HDR source can show a sideways or dimmer cover
- The saved subtitle preference stores an embedded track by index, and a quality change re-applies it on the new source as the first open does. A track picked on an HLS rendition can name a different KSPlayer track on Original. A track picked on Original can select an AVPlayer track on an Emby HLS rendition that already burns a subtitle into the picture, showing two subtitles
- A quality change resets a manually chosen audio track; the new source plays its default track while the picker marks index 0
- `applyPreferredSubtitleIfNeeded` checks only the media generation across its awaits, so a seek reopen that lands while it loads an external file can still receive the older selection
