VANMO XCODEGEN AND BUILD REFERENCE FOR LLMS
Last reviewed: 2026-08-31

CONFIGURATION AUTHORITY
- project.yml is the source of truth for application targets, package
  dependencies, source inclusion, resources, build settings, schemes, and
  entitlements.
- Packages/VanmoCore/Package.swift is the source of truth for the shared Swift
  package.
- Vanmo.xcodeproj is generated and committed. Never hand-edit
  Vanmo.xcodeproj/project.pbxproj.
- After changing project.yml, run:
  xcodegen generate
- Include the regenerated Vanmo.xcodeproj/project.pbxproj with the project.yml
  change and inspect the generated diff.

IOS UI TEST TARGET
- VanmoUITests is a bundle.ui-testing target with a dependency on Vanmo and
  TEST_TARGET_NAME set to Vanmo.
- The Vanmo scheme includes VanmoUITests in its test action.
- scripts/ios-ui.sh sets TEST_RUNNER_VANMO_UI_* environment variables. Xcode's
  test runner is expected to remove the TEST_RUNNER_ prefix when exposing them
  to VanmoDeviceInteractionTests.swift, which reads VANMO_UI_* variables.
  Simulator delivery was verified by the 2026-08-26 tab-navigation journey;
  physical-device delivery remains unverified until a signed device run is
  recorded.

STANDARD COMMANDS
- Resolve VanmoCore dependencies and run the four-stage baseline:
  ./init.sh
- Run the fast baseline, then Debug compile evidence for both apps:
  ./init.sh --full
- Compile one Debug application target without launching it:
  ./scripts/check-app-build.sh ios-simulator
  ./scripts/check-app-build.sh macos
- Check XcodeGen drift, target source whitelist, and VanmoCore UI imports:
  ./scripts/check-architecture-guards.sh
- Check the iOS UI target, generated project, Bash CLI, and Swift test source:
  ./scripts/check-ios-ui-cli.sh
- Run a bounded Simulator XCUITest interaction or journey:
  ./scripts/ios-ui.sh simulator tree --output /tmp/vanmo-tree.json
  ./scripts/ios-ui.sh simulator journey --name tab-navigation
- Run the same XCUITest commands on a signed physical device:
  ./scripts/ios-ui.sh device screenshot --output /tmp/vanmo.png
- Build, install, and launch the default iOS device target:
  ./run_device.sh
- Build, install, and launch an iOS Simulator target:
  ./run_device.sh --simulator
- Build and launch the native macOS app:
  ./run_device.sh --macos
- Select a configuration:
  ./run_device.sh --configuration Debug|Release
- Clean the script-managed DerivedData before building:
  ./run_device.sh --clean
- Launch an already built app without rebuilding:
  ./run_device.sh --launch-only
- Archive and export the iOS Release IPA:
  ./build_ipa.sh

COMMAND BOUNDARIES
- ./init.sh does not build or launch either app by default. After dependency
  resolution, its four baseline stages are VanmoCore tests,
  ./scripts/check-cloud-sync-multiplatform-scope.sh
  (including architecture structure guards),
  ./scripts/check-harness-docs.sh, and ./scripts/check-ios-ui-cli.sh.
- ./init.sh --full runs that fast baseline first, then
  ./scripts/check-app-build.sh all. The focused commands are
  ./scripts/check-app-build.sh ios-simulator and
  ./scripts/check-app-build.sh macos.
- Debug compile evidence is retained under build/app-build-evidence/. A
  successful compile proves only that the selected Debug target built in the
  recorded environment. It does not prove launch, UI, device, or CloudKit
  behavior.
- check-app-build.sh uses isolated DerivedData and
  build/app-build-evidence/SourcePackages, not Xcode Incremental Build
  cache. An Xcode Incremental Build does not replace this script. Never
  run ios-simulator and macos as two concurrent processes; use all or
  run them one after the other. Do not point Xcode at the evidence
  SourcePackages directory.
- The Harness documentation check requires Python 3 and fails when required
  governance files, routing links, or repository-local Markdown targets are
  missing.
- scripts/ios-ui.sh uses XCUITest for device and Simulator screenshot, tree,
  tap, type, swipe, wait, assert, and journey commands. simctl is limited to
  simulator boot plus launch/terminate and does not validate UI.
- XCUITest runs retain result bundles, logs, and exported attachments under
  build/ui-cli/runs/. Simulator XCUITest uses build/DerivedData-UITests-sim.
  A physical-device development team may be supplied through
  VANMO_DEVELOPMENT_TEAM or --team.
- The iOS UI CLI static check does not prove app compilation, signing, device
  execution, TEST_RUNNER argument delivery, or attachment export.
- run_device.sh defaults to Debug and selects the Vanmo or Vanmo-macOS scheme
  according to the requested platform.
- build_ipa.sh archives the Vanmo scheme with Release configuration and exports
  using ExportOptions.plist.
- Record the platform, configuration, destination, and whether a command only
  built, installed, launched, archived, or completed a user journey.

CLOUDKIT CONFIGURATION BOUNDARY
- CLOUDKIT_SYNC_ENABLED is defined for VanmoCore and for iOS/macOS Debug and
  Release. Personal-team fallback files Vanmo/Vanmo.entitlements and
  VanmoMac/Vanmo-Mac.entitlements omit iCloud.
- Debug and Release use Vanmo/Vanmo-Cloud.entitlements or
  VanmoMac/Vanmo-Mac-Cloud.entitlements (`iCloud.com.vanmo.app`).
- A Simulator Debug build, ./init.sh, or the static scope check cannot prove
  real CloudKit transport, account, conflict, or multi-device behavior.
- Real CloudKit still requires a signed device or Mac, an iCloud account, and
  the bound container.
